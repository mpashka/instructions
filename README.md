# Шаблоны инструкций для человека

Повторяющиеся действия на сайтах и в программах, которые ИИ-агент поручает человеку. Здесь лежат
**шаблоны**, а не инструкции: человеку отдаётся собранная из шаблона инструкция, в которой уже
стоят значения задачи — адреса, имена, секреты. По ней идут сверху вниз, не сверяясь ни с какой
таблицей параметров.

Правило, по которому пишутся инструкции, — `~/Projects/github/m_pashka/ai/rules/user-instructions.md`.

Репозиторий — `git@github.com:mpashka/instructions.git`, **публичный**: ничего рабочего, личного и
секретного. Конкретные значения живут в файле значений у задачи.

## Как пользоваться

```bash
render=~/Projects/github/m_pashka/instructions/render
$render <задача>/…-values.yaml [шаблон ...]           # собрать; без шаблонов — все разделы файла
$render --clean <задача>/…-values.yaml [шаблон ...]   # затереть и удалить; без шаблонов — всё собранное задачей
```

Рендерер печатает путь к собранному и список подставленных полей — без значений. Собранное
ложится в `~/Projects/home/secrets-out/instructions/<проект>/<задача>/<проект>-<задача>-<шаблон>.html`
(или `.md`; вне git; другой корень — `--out` или `$INSTRUCTIONS_OUT`), каталоги `0700`, файлы `0600`.

- **Имя файла уникально** — его открывают по имени в IDE, а `instruction.html` у всех шаблонов одинаковый.
- **Проект и задачу рендерер находит сам** по месту файла значений: проект — ближайший каталог выше с
  `AGENTS.md` или `.git`, задача — путь от проекта до каталога файла значений без `docs/requests/`
  (в имени — последний его сегмент). Файл значений вне проекта или в его корне — ошибка.

🚨 **ИИ-агент собранную инструкцию не читает**: в ней бывают секреты открытым текстом, и в
стенограмму сессии они попасть не должны. Проверять можно только наличие файла и отсутствие
`{{` (`grep -c`). Человеку называется путь к файлу. Использовали — `--clean` той же задачей.

## Файл значений

YAML у задачи, в git рядом с ней. Раздел на шаблон, в разделе — все поля шаблона:

```yaml
chatgpt-gpt-oauth-action:
  gpt_name: Learning API
  client_id: example-gpt-actions
  client_secret: {vault: ~/Projects/home/secrets/example.yml, key: vault_example_client_secret}
```

Секрет — только ссылкой `{vault: <файл>, key: <ключ>}`: рендерер сам расшифровывает его
`ansible-vault view` (пароль — из `~/.ansible.cfg`). Относительный путь к vault-файлу считается от
файла значений. Незаполненное или лишнее поле, неизвестный шаблон, нет ключа в vault — ошибка с
именем поля и файла, а не молча оставленный `{{…}}`.

## Шаблон

Каталог `<шаблон>/`:

| Файл | Что |
|---|---|
| `fields.yaml` | `title` и `fields`: поле → `about` (что это) и `example` (пример, на нём гоняется тест) |
| `instruction.html` | инструкция с экранами: рисунок диалога, обведено что нажимать, кнопки «Копировать» у значений |
| `instruction.md` | инструкция без экранов, где рисунок ничего не добавляет |

- Место подстановки — `{{имя_поля}}` (строчные латинские, цифры, `_`). В HTML значение
  экранируется, в Markdown — нет. Поле в тексте без объявления в `fields.yaml` и объявление без
  поля в тексте — ошибка.
- Значение подставляется как значение: без пояснений внутри. Нужна фраза вокруг — она в шаблоне.
- Пометка «это шаблон» — между `<!-- template-note:begin -->` и `<!-- template-note:end -->`:
  человек, открывший шаблон, видит её, в собранной инструкции её нет.
- Экран сайта — HTML по образцу `dialogs/_template.html`: самодостаточный, без внешних ресурсов,
  тёмная тема, без скриншотов. Лучше один раз увидеть, чем читать «третье поле под заголовком».
- «ИИ-агент», а не «агент». Что вернуть — готовой строкой для отправки ИИ-агенту или командой.
  Что ИИ-агент сделает с ответом — не пишется.

Тест — `python3 -m unittest discover -s tests`: рендерер на подменённом vault и сборка каждого
шаблона на его примерах. Меньше секунды, без сети и без настоящего vault.

## Раскладка

| Путь | Что |
|---|---|
| `render` | рендерер: python3 + PyYAML |
| `<шаблон>/` | шаблон: `fields.yaml` и `instruction.html` или `instruction.md` |
| `tests/` | тест рендерера и шаблонов |
| `dialogs/<сайт>.html` | диалоги многоязычного сайта: рисунок, универсальные имена полей (`data-field`), переключатель RU/EN |
| `dialogs/_template.html` | образец HTML-рисунка диалогов — копировать, а не править |
